# Veriluvrionikrousdorn (VLR)

Любительская операционная система для x86-64. Ядро написано на Rust (`no_std`).
Дальняя цель — своё ядро и свой формат приложений с расширением `.vlr`.

Сейчас это веха «многозадачность», версия **0.3.0**. Ядро загружается в QEMU,
показывает баннер, поднимает исключения и прерывания и вытесняюще переключает
потоки ядра. Оболочка `vch` — один из потоков, рядом с ней крутятся фоновые
задачи. Системные вызовы, Btrfs и запуск `.vlr` ещё нет.

## Что уже работает

- Загрузка через [bootloader](https://github.com/rust-osdev/bootloader) 0.11
  (rust-osdev): BIOS-образ диска, ядро получает карту памяти и framebuffer.
- Баннер `Veriluvrionikrousdorn` и версия на экране и в последовательный порт.
- Свой GDT и TSS, IDT, PIC 8259.
- Исключения: breakpoint, page fault, double fault (у двойного отказа свой стек),
  а также general protection — он нужен, чтобы ошибка сегмента не уходила в никуда.
- Таймер PIT (IRQ0, 100 Гц) и клавиатура PS/2 (IRQ1). Нажатия попадают в экран.
- Последовательный порт COM1 (115200 8N1), в том числе как ввод оболочки.
- Паника ядра пишет сообщение в serial и, если экран свободен, в framebuffer.
- Физические кадры 4 КиБ по карте загрузчика (`vlr-memory`): выделение,
  освобождение, учёт total/used/free.
- Страницы: смещение физической памяти от загрузчика, `map_4k` / `unmap_4k`
  (снятие возвращает кадр в пул), identity-отображение одного кадра.
- Куча ядра с глобальным аллокатором: старт 256 КиБ, рост кусками по 256 КиБ
  до 16 МиБ. В ядре работают `Box`, `Vec`, `String`, `BTreeMap`.
- Потоки ядра в `vlr-sched`: у каждого свой стек из кучи (64 КиБ),
  round-robin по каждому тику PIT (100 Гц), `spawn` / `yield_now` / `sleep` /
  `exit` / `kill`. Вышедшая задача исчезает из списка, её стек освобождается.
- Оболочка `vch` — отдельная задача. Рядом с ней с самого старта работают
  `ticker` (спит) и `spinner` (крутится и вытесняется). Приглашение:
  `user@::vch#~ ` (имя `user` — заглушка, `~` — домашний каталог).
  Команды: `help`, `clear`, `echo`, `version`, `about`, `pwd`, `whoami`,
  `uname`, `ticks`, `mem`, `history`, `ps`, `spawn`, `kill`.
  `ps` печатает id, имя, состояние и тики. `spawn ticker` или `spawn spinner`
  заводит ещё одну такую задачу. `kill <id>` останавливает задачу, кроме idle.
  Неизвестная команда печатает `unknown command`.
- Автопроверка: юнит-тесты кадров, приглашения и заголовка `.vlr`, плюс загрузка
  в QEMU без окна. Успех — код выхода 33 (`isa-debug-exit`). Проверяются баннер,
  куча, страницы, одновременный прогресс двух потоков без `yield`, пробуждение
  после `sleep`, исчезновение вышедшей задачи и page fault с адресом.

Текст на экране пока только латиница: встроенный шрифт 8×8 покрывает U+0000…U+007F.
Поэтому сообщения оболочки на английском, а эта документация — на русском.

## Чего в этой вехе нет

- Отдельных адресных пространств: все потоки живут в ядре, в одном отображении.
- Настоящих системных вызовов (номера зарезервированы, диспетчер отклоняет вызов).
- Драйвера диска. Есть только трейт блочного устройства.
- Файловой системы. VFS и модуль Btrfs соединены типами, операции возвращают
  «не реализовано».
- Запуска `.vlr`. Парсер проверяет магию `\x7FVLR` и 32-байтный заголовок.

## Сборка и запуск

Нужны nightly Rust (файл `rust-toolchain.toml` выбирает его сам и ставит
`rust-src` с `llvm-tools`), цель `x86_64-unknown-none` и QEMU
(`qemu-system-x86_64`). Тест дополнительно вызывает `timeout` из coreutils.
`llvm-tools` нужен загрузчику: он вызывает `llvm-objcopy`, чтобы собрать BIOS-образ.

Из корня репозитория:

```bash
cargo run
```

Собирает ядро, BIOS-образ `target/vlr-bios.img` и запускает QEMU без окна.
Этот терминал — последовательная консоль: можно набирать команды `vch`.
До баннера загрузчик пишет в тот же порт свой журнал (`INFO : …`).
Клавиатура PS/2 в этом режиме не подключена к терминалу, она работает в окне:

```bash
cargo run -- --gui
```

Другие команды:

```bash
cargo run -- build    # только образ, без QEMU
cargo run -- test     # юнит-тесты и безголовая загрузка
make run
make test
make build
```

Первая сборка дольше обычной: скачиваются крейты и компилируется загрузчик.
Проверка `cargo run -- test` сама поднимает QEMU дважды. Первый запуск печатает баннер, ждёт тики таймера, проверяет память и страницы,
запускает несколько потоков (они крутятся одновременно, один спит и просыпается,
один сразу выходит и исчезает из списка), затем читает снятый адрес.
Обработчик page fault пишет этот адрес и выходит через `isa-debug-exit`.
Второй запуск — оболочка: `help`, `echo`, `history`, `mem`, `ps`, неизвестная
команда (через serial) и `pwd` (через PS/2, `sendkey`).

## Раскладка модулей

Каждый крейт делает одно дело. Ядро только вызывает их по порядку и не содержит
драйверов.

| Крейт | За что отвечает |
| --- | --- |
| `kernel` | Точка входа, паника, баннер, порядок инициализации |
| `vlr-arch` | GDT, TSS, IDT, PIC, исключения, включение прерываний, `isa-debug-exit` |
| `vlr-drivers` | UART, текст во framebuffer, PS/2, PIT, очередь ввода, трейт `BlockDevice` |
| `vlr-console` | Общий вывод на экран и в serial, макросы `print!` / `println!` |
| `vlr-memory` | Кадры, таблицы страниц (смещение и map/unmap), куча ядра |
| `vlr-sched` | Потоки ядра, round-robin по PIT, spawn/yield/sleep/exit/kill |
| `vlr-syscall` | Номера `read` / `write` / `exit` и диспетчер-заглушка |
| `vlr-vfs` | Интерфейс файловой системы и точек монтирования поверх `BlockDevice` |
| `vlr-btrfs` | Btrfs. Реализует интерфейс VFS, но том ещё не читает |
| `vlr-loader` | Черновик заголовка `.vlr`, пути приложений, загрузчик-заглушка |
| `vch` | Оболочка. Зависит только от трейта ввода-вывода, не от драйверов |
| `xtask` | Образ диска и запуск QEMU. Это программа `cargo run` |

Новый драйвер добавляется в `vlr-drivers` и регистрирует свой IRQ через
`vlr-arch`. Новая файловая система реализует `vlr_vfs::Filesystem` и читает
`BlockDevice`, не трогая клавиатуру и GDT. `vch` позже заменится файлом
`/Apps/vch/vch.vlr`: цикл приглашения у него уже отделён от ядра.
Как устроены кадры, смещение и куча — в [docs/memory.md](docs/memory.md).
Потоки и переключение контекста — в [docs/sched.md](docs/sched.md).

## Каталоги приложений

Код, данные и библиотеки лежат раздельно:

- `/Apps/vch/vch.vlr` — программа;
- `/AppData/vch/` — настройки, данные, кэш;
- `/Libs/` — общие библиотеки;
- `/Users/user` — дом, в приглашении это `~`.

Почему так и как загрузчик будет искать файл, данные и библиотеки —
в [docs/layout.md](docs/layout.md). Имя `user` временное, до подсистемы учёток.

## Формат `.vlr`

Черновик заголовка, магия `\x7FVLR`, секции и импорт по имени файла, без пути —
в [docs/vlr-format.md](docs/vlr-format.md). Первое приложение формата — `vch`.

## Дорожная карта

1. **Память.** Сделано в 0.2.0, в 0.3.0 куча ещё и растёт, а `unmap_4k`
   возвращает кадр. См. [docs/memory.md](docs/memory.md).
2. **Многозадачность.** Сделано в 0.3.0: потоки ядра, вытеснение по PIT,
   `vch` как одна из задач. См. [docs/sched.md](docs/sched.md).
   Пользовательских процессов с отдельным адресным пространством ещё нет.
3. **Системные вызовы.** Следующая веха. Ловушка из кольца 3 в `vlr-arch` и
   рабочий `vlr-syscall` (`read`, `write`, `exit`, затем каталоги и процессы).
4. **Блок.** Драйвер ATA или AHCI в `vlr-drivers`, который реализует уже
   существующий `BlockDevice`.
5. **VFS.** Таблица монтирования в `vlr-vfs`: путь, файловая система, устройство.
   Для неё как раз нужна куча.
6. **Btrfs, только чтение.** `vlr-btrfs` открывает суперблок (`_BHRfS_M` по
   смещению `0x10000`), каталоги и файлы. Этого хватит, чтобы загрузчик
   прочитал `/Apps` и `/Libs`.
7. **Btrfs, запись.** Создание `/AppData`, настройки, кэш. Запись идёт вторым
   шагом, после устойчивого чтения.
8. **Загрузчик `.vlr`.** Разобрать секции, подтянуть библиотеки
   (сначала `/Apps/<имя>/`, потом `/Libs/`), прыгнуть на точку входа.
9. **`vch` как первое приложение.** Вынести нынешнюю оболочку в
   `/Apps/vch/vch.vlr`, данные держать в `/AppData/vch/`, имя пользователя
   брать из будущих учёток вместо заглушки `user`. Приглашение остаётся
   `username@::vch#~ `.
