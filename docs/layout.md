# Каталоги приложений VLR

Иерархия на втором IDE-диске. Писать можно в `/AppData/<приложение>/` и в
дом единственного пользователя `/Users/<имя>/`. `/Apps` и `/Libs` для программ
только для чтения. Файл `/System/account` хранит эту одну учётку.

## Корни

| Путь | Что лежит |
| --- | --- |
| `/Apps/<имя>/` | Файлы программы, включая исполняемый `<имя>.vlr` |
| `/AppData/<имя>/` | Настройки, пользовательские данные и кэш этого приложения |
| `/Libs/` | Общие библиотеки |
| `/Users/<пользователь>/` | Домашний каталог сессии. В приглашении vch показывается как `~` |
| `/System/` | Зарезервировано под ядро и служебные файлы. Пока пусто |

Первое приложение — оболочка `vch`:

| Назначение | Путь |
| --- | --- |
| Исполняемый файл | `/Apps/vch/vch.vlr` |
| Каталог программы (частные файлы и частные библиотеки) | `/Apps/vch/` |
| Данные | `/AppData/vch/` (`config/`, `data/`, `cache/`) |
| Общие библиотеки | `/Libs/` |
| Дом пользователя-заглушки | `/Users/user` |

## Почему имена такие

Код программы, её данные и библиотеки разделены специально.

- Обновление приложения заменяет `/Apps/vch/` и не трогает `/AppData/vch/`.
  Настройки и кэш переживают замену `vch.vlr`.
- Данные можно копировать и чистить отдельно от кода. Кэш лежит в
  `/AppData/vch/cache/` и его можно удалить, не трогая `config/`.
- Общие библиотеки собраны в `/Libs/`, а не размазаны по каталогам приложений.
  Частная копия, если она нужна только одному приложению, лежит рядом с
  исполняемым файлом и имеет приоритет при поиске.
- Домашний каталог — это каталог пользователя, а не каталог приложения.
  `~` в приглашении `vch` означает «сейчас мы в доме», а не «мы внутри vch».

Имена короткие и читаются одинаково в документации и в заголовке `.vlr`.
Общая свалка вроде `/usr/bin` здесь не подходит: у приложения есть каталог,
а не один файл среди чужих.

## Как загрузчик найдёт части `vch`

Пользователя пока нет. Имя `user` — заглушка в `vlr-loader::PLACEHOLDER_USER`.
Его подставит будущая подсистема учёток; в файл `.vlr` оно не записывается.

1. Имя приложения — `vch` (из командной строки или из каталога, если дали полный путь).
2. Исполняемый файл — `/Apps/vch/vch.vlr`. Если передали полный путь, берётся он,
   а имя приложения — последний каталог перед файлом.
3. Заголовок `.vlr` перечисляет библиотеки по имени файла, без каталога
   (`libdraw.vlr`, не `/Libs/libdraw.vlr`).
4. Для каждого такого имени поиск идёт так:
   - `/Apps/vch/<файл>` — частная копия, поставляемая вместе с программой;
   - `/Libs/<файл>` — общая библиотека.
5. Корень данных процесса — `/AppData/vch/`. `vch` пишет туда `history` и
   `settings`. Новый каталог приложения создаётся командой `mkdir`, если путь
   входит в разрешённую зону.
6. Домашний каталог сессии — `/Users/user`. Пока оболочка в нём, приглашение
   показывает `~`: `user@::vch#~ `. `cd /Apps` меняет каталог, `cd` без
   аргумента возвращает домой.

Ядро при старте открывает `/Apps/vch/vch.vlr`. Если файл не читается, то же
приглашение ведёт запасная задача ядра. Пути от этого не меняются.
