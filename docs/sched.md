# Потоки ядра

Веха 3, крейт `vlr-sched`. Поток ядра живёт в адресном пространстве ядра.
С вехи 0.4.0 у пользовательской задачи свой CR3; планировщик загружает его
при переключении. `vch` с 0.5.0 — такая задача.

## Задача

У задачи есть номер, короткое имя, состояние (`running`, `ready`, `sleeping`),
счётчик тиков и стек 64 КиБ из кучи. Поток, на котором стартовало ядро, становится
задачей `idle` (id 0) и своего стека из кучи не получает: он уже стоит на стеке
загрузчика. `idle` нельзя снять через `kill`.

Состояния, которых в `ps` не видно: вышедшая задача помечается мёртвой и при
ближайшем планировании освобождает стек. Пока она ещё исполняется, её стек не
трогают.

## Переключение

`context_switch` сохраняет rbp, rbx, r12–r15 и RSP и восстанавливает их у другой
задачи. Новый поток начинает с трамплина: тот включает прерывания и зовёт
функцию, переданную в `spawn`. Когда функция возвращается, задача делает `exit`.

Таймер PIT (IRQ0, 100 Гц) после обработки прерывания и EOI зовёт планировщик.
EOI до переключения нужен, чтобы следующий тик пришёл, пока новая задача уже
работает. Каждый тик текущая задача получает +1 к счётчику, спящие с
истёкшим сроком становятся `ready`, и round-robin выбирает следующую готовую.
Если готова только текущая, переключения нет.

## Вызовы

- `spawn(name, entry)` — стек из кучи, задача становится `ready`.
- `yield_now` — отдать квант.
- `sleep(ticks)` — не раньше чем через столько тиков PIT.
- `exit` — больше не планировать этот поток.
- `kill(id)` — то же для другого id. Свой id тоже завершает текущий поток.

На старте оболочки ядро заводит три задачи: `vch`, `ticker` (спит по 50 тиков)
и `spinner` (крутится и вытесняется). Команда `spawn ticker` или `spawn spinner`
добавляет ещё одну. `ps` показывает id, имя, состояние и тики.
